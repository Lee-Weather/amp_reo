# 实验笔记更新规范（exp_ada_x 系列）

## 目标文件

```
czy/exp1/exp1.md
```

**分工**：

| skill | 职责 |
| --- | --- |
| **lab-notebook（本 skill）** | 编号、索引表、实验章节结构、写回结论 |
| `isaac-diag-eval`（可选） | 跑 `eval_isaac_diag.py`，产出 E1~E8 诊断数值（需 CSV，无 CSV 时用训练日志数据） |

新建/更新实验必须遵循本 skill 的章节模板。

## 一、实验编号规则

### 1.1 格式（跨版本统一序列）

```
exp_ada_{n}    或    exp_ada_{n}.{m}（微调重试）
```

- **主编号（`exp_ada_{n}`）**：n 从 1 开始全局递增（exp_ada_1、exp_ada_2…），每个新实验占一个新编号。
- **微调（子编号 `.{m}`）**：`exp_ada_{n}` 未达标 → 微调优化重训 → `exp_ada_{n}.{m}`（m 递增）；仍不达标 → `exp_ada_{n}.2`…
- **跨版本说明**：`exp_ada` 前缀对应项目 X1_29_re0_ada。旧项目（X1_29_re0）阶段式规则下的 exp0/exp0.1/exp0.2 记录在索引表中**只读保留**，不参与新序列。

| 示例 | 含义 | 何时使用 |
| --- | --- | --- |
| `exp_ada_1` | 系列首个实验 | 已使用（速度域聚焦 + step_scale 自适应 + URDF 旧约定） |
| `exp_ada_2` | 下一个新实验 | 新目标/新方向 |
| `exp_ada_2.1` | exp_ada_2 的微调1 | exp_ada_2 未达标，小改重训 |
| `exp_ada_3` | 再下一个 | exp_ada_2（或其微调）达标后开新方向 |

**规则**：
- 编号不可变：失败尝试保留编号，索引表状态标「失败」，不删除不跳号
- 历史编号（exp0/exp0.1/exp0.2）只读保留，新实验一律用 exp_ada_x

### 1.2 微调（子编号 `.{m}`）

`exp_ada_{n}` **未达标**时，修改参数后重训 → 新建 `exp_ada_{n}.{m}`（m 递增）：

- 微调范围：仅改 1~3 项奖励权重、小参数、小幅修正
- 微调继承父实验的修改编号（见 §3）

### 1.3 新实验（新建主编号 `exp_ada_{n+1}`）

满足**任意一条**时，新建主编号：

- `exp_ada_{n}` 或其微调 `exp_ada_{n}.{m}` **达标验收目标** → 新建 `exp_ada_{n+1}` 设新目标
- 跨 ≥2 个模块的大改（新增/删除奖励、改 IK 逻辑、改 URDF）→ 即使未达标也新建主编号
- 切换训练任务（如 Flat → Rough）→ 新建主编号并在 §5 标注 task 变化

### 1.4 原地更新（不改编号）

满足**任意一条**时，不新建编号，直接更新现有实验的 §7：

- 训练中途观察日志，仅做趋势分析（未训完）
- 训练完成后补充结果数据
- 发现记录有误，修正数值

## 二、索引表更新规则

文件顶部 `## 实验索引` 表格，**每新建实验必须先加一行**：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 编号 | ✅ | 如 `exp_ada_2` |
| 日期 | ✅ | `YYYY-MM-DD` |
| 摘要 | ✅ | 一句话：改了什么、结果判定 |
| 状态 | ✅ | 见下表 |
| Task ID | ✅ | GM 任务 ID，如 `TASK_20260730_200` |
| GM账号 | ✅ | 训练使用的 GM 账号邮箱，如 `yijed24226@barumart.com` |
| checkpoint | ✅ | 最终模型文件名，如 `model_3000.pt` |

**状态枚举**：

| 状态 | 何时使用 |
| --- | --- |
| 待训练 | 方案已写，未开训 |
| 训练中 / 续训中 | 正在跑 |
| 已测试 | 训练完成，结论已写 |
| 失败 | 未达验收目标，保留教训 |
| 已废弃 | 方向否定，不再续做 |

## 三、修改内容编号规则

§3「修改内容」内部用**修改一、修改二...** 编号：

- **微调（`exp_ada_{n}.{m}`）**：修改编号**继承**父实验。如 exp_ada_1 有「修改一、二」，exp_ada_1.1 接「修改三」。
- **新实验（`exp_ada_{n+1}`）**：修改编号**重置**，从「修改一」重新开始。

```markdown
## 实验 exp_ada_1（系列首训）
### 修改一：…
### 修改二：…

## 实验 exp_ada_1.1（微调1，继承）
### 修改三：…    ← 接续 exp_ada_1

## 实验 exp_ada_2（新实验，重置）
### 修改一：…    ← 重新从「修改一」开始
```

## 五、Agent 工作流

### 5.1 新建实验

1. **判断编号**：
   - 上一实验**达标**（或跨模块大改/换任务）→ 新建 `exp_ada_{n+1}`（修改编号重置）
   - 上一实验**未达标**且仅小改 → 微调 `exp_ada_{n}.{m}`（修改编号继承父实验）
2. 在索引表**末尾**追加一行
3. 在文件**末尾**追加完整实验章节（§1~§7，§7 占位「待训练完成后补充。」）
4. §1 必须引用上一实验 §7 的**具体数值**，禁止只写「效果不好」

### 5.2 训练完成后更新结果

1. 用 `gm task data get` 拉训练曲线关键点数据
2. 将 Mean reward、Episode length、各奖励项最终值填入 **§7**
3. 写分级结论（✅达标 / ⚠️部分达标 / ❌未达标）
4. 更新索引表：状态 → `已测试` 或 `失败`；摘要补关键判定

### 5.3 训练中途更新（不改编号）

1. 不新建实验，直接在现有 §7 追加「训练进度趋势」小节
2. 索引表状态保持「训练中」

### 5.4 禁止事项

- ❌ 不编造未拉取的数据
- ❌ 不删除失败实验记录
- ❌ 不跳号（exp_ada_2 之后是 exp_ada_3，不要直接 exp_ada_5）
- ❌ 结论禁止笼统「还行」，必须分级 + 量化

## 六、快速决策表

| 场景 | 编号 | 动作 |
| --- | --- | --- |
| 系列首个实验 | `exp_ada_1` | 已使用；§1 引用旧项目 exp0 系列结论 |
| 新方向/新目标 | `exp_ada_{n+1}` | 新建主编号，§3 修改编号重置 |
| 未达标，小改重训 | `exp_ada_{n}.{m}` | 微调，§3 修改编号继承父实验 |
| 训练失败但教训明确 | 原编号 | 更新 §7 + 状态「失败」 |
| 训练中途看日志 | 原编号 | §7 追加趋势，不改编号 |
| 跨模块大改（未达标也新编号） | `exp_ada_{n+1}` | 重置修改编号 |
| 切换任务（Flat→Rough） | `exp_ada_{n+1}` | 新编号，§5 标注 task 变化 |

## 七、注意事项

1. **§1 教训必须可量化**：至少 2 个来自训练日志或 isaac_diag 的数
2. **失败同样完整记录 §7**：失败原因写在根因分析
3. **索引表与正文状态一致**
4. **结论分级**：✅达标 / ⚠️部分达标 / ❌未达标，禁止笼统表述
5. **GM 数据获取**：用 `gm task data get --task-id ... --data-key "Train/mean_reward"` 拉曲线

## 八、数据归档规范

`czy/data/{实验编号}/` 下每个实验子文件夹**只允许存放三个文件**：

| 文件 | 说明 |
| --- | --- |
| `model_{N}.pt` | 训练结果模型 checkpoint |
| `play_output.mp4` | play 回放视频 |
| `isaac_diag.csv` | play 回放诊断 CSV |

禁止在该目录存放 `model_isaac_csv.pt`、分析 PNG、日志等额外文件。分析图/临时打包文件如需保留，放 `czy/analysis/` 或项目外目录。
