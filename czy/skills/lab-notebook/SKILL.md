- 已有`exp_1.1`保留历史名称。索引按发生顺序保留，不根据新标签伪造训练时间顺序。

### 1.2 何时新建实验

修改训练奖励、采样分布或优化配置后启动新一轮训练，使用下一个exp1.x编号；从既有checkpoint接着训练也应注明模型来源并使用本轮新编号。重训不能覆盖父实验。

### 1.3 何时只更新结果

训练中途观察、完成后补充分析、纠正错误、同checkpoint重新回放均更新原实验§7，不新占训练编号。单独提出下轮方向时先写在当前§7；要建立正式待训练实验则按模板补齐§1~§6。

## 二、索引表更新规则

文件顶部 `## 实验索引` 表格，**每新建实验必须先加一行**：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 编号 | ✅ | 如 `exp1.4` |
| 日期 | ✅ | `YYYY-MM-DD` |
| 摘要 | ✅ | 一句话：改了什么、结果判定 |
| 状态 | ✅ | 见下表 |
| Task ID | ✅ | GM 任务 ID，如 `TASK_20260730_200` |
| GM账号 | ✅ | 训练使用的 GM 账号邮箱，如 `yijed24226@barumart.com` |
| checkpoint | ✅ | 最终模型文件名，如 `model_3000.pt` |

**状态枚举**：

| 状态 | 何时使用 |
| --- | --- |
| 待训练 | 方案已写，未开训 |
| 训练中 / 续训中 | 正在跑 |
| 训练完成，待验收 | 训练已结束，模型取回或回放验收尚未完成；不得冒充已测试 |
| 已测试 | 训练完成，结论已写 |
| 失败 | 未达验收目标，保留教训 |
| 已废弃 | 方向否定，不再续做 |

## 五、Agent 工作流

### 5.1 新建实验

1. **判断编号和种子**：当前实验为`exp1.4`，下一轮为`exp1.5`，固定seed=5；未经用户明确同意不得进入exp2。后续在exp1.x内递增，不因跨模块修改自动升级主编号。
2. 在索引表**末尾**追加一行
3. 在文件**末尾**追加完整实验章节（§1~§7，§7 占位「待训练完成后补充。」）
4. §1 必须引用上一实验 §7 的**具体数值**，禁止只写「效果不好」

### 5.2 训练完成后更新结果

1. 用 `gm task data get` 拉训练曲线关键点数据
2. 将 Mean reward、Episode length、各奖励项最终值填入 **§7**
3. 写分级结论（✅达标 / ⚠️部分达标 / ❌未达标）
4. 更新索引表：状态 → `已测试` 或 `失败`；摘要补关键判定

### 5.3 训练中途更新（不改编号）

1. 不新建实验，直接在现有 §7 追加「训练进度趋势」小节
2. 索引表状态保持「训练中」

### 5.4 禁止事项

- ❌ 不编造未拉取的数据
- ❌ 不删除失败实验记录
- ❌ 不跳过已约定的exp1.x编号；未经用户同意不得进入exp2
- ❌ 不默认追加seed7/11或其他随机种子
- ❌ 结论禁止笼统「还行」，必须分级 + 量化

## 六、快速决策表

| 场景 | 编号 | 动作 |
| --- | --- | --- |
| 当前下一轮训练 | `exp1.6` | 写完整方案，seed=5，注明续训或从零及模型来源 |

## 七、注意事项

1. **§1 教训必须可量化**：至少 2 个来自训练日志或 isaac_diag 的数
2. **失败同样完整记录 §7**：失败原因写在根因分析
3. **索引表与正文状态一致**
4. **结论分级**：✅达标 / ⚠️部分达标 / ❌未达标，禁止笼统表述
5. **GM 数据获取**：用 `gm task data get --task-id ... --data-key "Train/mean_reward"` 拉曲线

## 八、数据归档规范

`czy/data/{实验编号}/` 下每个实验子文件夹**只允许存放三个文件**：

| 文件 | 说明 |
| --- | --- |
| `model_{N}.pt` | 训练结果模型 checkpoint |
| `play_output.mp4` | play 回放视频 |
| `isaac_diag.csv` | play 回放诊断 CSV |

禁止在该目录存放 `model_isaac_csv.pt`、分析 PNG、日志等额外文件。分析图、训练曲线、摘要和回放元数据等长期记录放 `czy/exp1/{实验编号}_evaluation/`，不与三件套混放。

`czy/analysis/` 仅作为可清理的临时工作目录：部署包、启动脚本、中间CSV和短测产物验证完成后删除；如需留存证据，先迁入对应实验 evaluation 目录并更新笔记链接。后续回放优先使用系统临时目录，结束后清理，不在analysis堆积一次性文件。

复用工具位于 `scripts/amp_tools/`，调用参数见该目录README；不要重新在 `czy/validation/` 创建一次性脚本。状态文件和训练日志可放czy/exp1/{实验编号}_training.json/log；训练曲线、诊断图和回放记录放对应evaluation目录。不要恢复已清理的artifacts目录。
